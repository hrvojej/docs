# Gap analysis framework

**As-of:** 2026-09-21

## Unit of analysis

Gap analysis is done per **specific product thesis**, never at buzzword level.

## Stack decomposition

Each thesis is decomposed into:

1. sensing / hardware
2. embedded / edge compute
3. communications
4. control / autonomy
5. perception / ML / analytics
6. data engineering
7. platform / cloud
8. UI / workflow
9. cybersecurity
10. mechanical integration
11. power / drives
12. manufacturing
13. testing / certification
14. installation / commissioning
15. service / support
16. sales channel / buyer access
17. data rights / training data
18. IP / licensing

## Gap labels

- **G0 Native:** already proven in-house
- **G1 Adjacent:** exists in-house but not productized for this use
- **G2 Learnable:** can be built in 6–18 months
- **G3 Partner gap:** external specialist preferred
- **G4 Acquisition gap:** strategic capability missing
- **G5 Structural blocker:** regulation/economics/channel make thesis unattractive

## Cross-company synergy test

Opportunity should explicitly show which companies contribute:
- domain hardware
- sensing/control
- software/data
- R&D/testing
- manufacturing
- deployment/service
- customer channel

If only one capability is internal and the rest is commodity integration, strategic value may be weak.

## Defensibility test

Potential moats:
- installed base
- proprietary equipment telemetry
- domain models
- certified hardware
- difficult field deployment
- integrated hardware/software/service
- long-term service contracts
- reference projects
- switching costs
- regulatory qualification
- manufacturing know-how

## Economics checklist

- ASP / contract value
- hardware gross margin
- software ARR
- service attach rate
- lifecycle revenue
- CAC / channel
- deployment cost
- support cost
- warranty risk
- CAPEX/tooling
- engineering NRE
- payback for customer
